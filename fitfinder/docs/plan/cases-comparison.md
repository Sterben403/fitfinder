# Сравнение моделей поставки по трём кейсам

| Критерий | (а) ИС документооборота в госоргане по тендеру | (б) Мобильный продукт стартапа с непроверенной гипотезой | (в) Миграция монолита банка в облако |
|---|---|---|---|
| Неопределённость требований | Низкая: требования зафиксированы в техзадании тендера | Очень высокая: неизвестно, нужен ли продукт рынку | Средняя: функции системы известны, неизвестны технические проблемы переноса |
| Стоимость ошибки | Высокая: штрафы, срыв госконтракта, претензии проверяющих | Низкая: ошибка быстро исправляется, это часть обучения на рынке | Очень высокая: простой платежей, потеря денег и данных клиентов |
| Регуляторика | Высокая: закон о госзакупках, требования ИБ, стандарты документации | Минимальная (только базовые правила магазинов приложений и персональных данных) | Высокая: требования регулятора финрынка, PCI DSS, защита персональных данных |
| Зрелость заказчика | Низкая в гибких подходах: ждёт документы, акты, приёмку по этапам | Высокая вовлечённость: основатель рядом и быстро принимает решения | Высокая: собственный ИТ-департамент, архитекторы, служба безопасности |
| Распределённость команды | Подрядчик и заказчик в разных организациях, общение через официальные письма | Маленькая команда, одна локация или удалённо, общение напрямую | Высокая: несколько команд банка, облачный провайдер, внешние вендоры |
| Тип контракта | Фиксированная цена (Fixed Price) по результатам тендера | Time & Material / собственные средства и инвестиции | Смешанный: рамочный договор + оплата по этапам (волнам) |

## Выводы

| Кейс | Модель поставки | Ритм принятия решений | Переменная величина |
|---|---|---|---|
| (а) Госорган | Каскадная (V-модель) | По этапам и вехам с формальной приёмкой (акты); изменения только через процедуру управления изменениями | **Срок** — объём и качество закреплены ТЗ и контрактом, при отклонениях сдвигается срок через допсоглашение |
| (б) Стартап | Scrum (Lean Startup: построй — измерь — научись) | Спринты 1–2 недели, решение «продолжать / менять гипотезу» после каждого спринта по метрикам | **Объём** — срок и качество фиксированы, функции MVP добавляются или выбрасываются по результатам проверки гипотезы |
| (в) Банк | Гибридная: план с контрольными воротами (go/no-go) + итеративные волны миграции (Kanban/Scrum внутри волн) | Волна раз в 1–2 месяца с решением go/no-go; внутри волны — еженедельно | **Срок отдельных волн** — качество (надёжность, безопасность) неизменно, волна переносится, если не прошла проверки |
